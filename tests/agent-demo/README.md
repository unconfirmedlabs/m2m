# Shared demo test vectors

`accounting-vectors.json` contains synthetic arithmetic/replay inputs only:
**TEST FIXTURE — no live agents or payments.** It is not a production demo mode,
an event transcript or evidence that the HTTP/UI integration works.

UI and backend tests should consume these same inputs through their actual
reducers. The root check (`npx tsx scripts/test-agent-demo-vectors.ts`) verifies
the expected prices against the existing native price function and checks the
other expected arithmetic/UTF-8/source identities independently. Passing that
oracle does not establish F10–F13; actual consumers still need their own tests.

The fixtures cover integer amounts beyond IEEE-754 precision, one cumulative
rounding operation, replacing signed ceilings rather than summing them, advance
redemption above delivery, unknown chain observations, independently confirmed
refunds with gas separate, split UTF-8 output and duplicate event/source identities.
Terminal channel displays retain historical authorization/reservation/delivery
counters, but independently confirmed closed/refunded state has zero active
redemption exposure. A pending terminal transaction retains the conservative gap;
model completion, a requested close or an unavailable RPC is not confirmation.
Production imports must never reference this directory.

`economic-session.json` provides structurally complete signed payment inputs for
test harnesses. `npm run agent-demo-economic-fixture-tests` regenerates them
through the actual `StreamingEngine` and compares the checked result. It uses
public test-only economic seeds, ephemeral private journals and no network or
funds. It checks signatures, byte commitments, credit exhaustion, renewal,
in-process journal reopen and duplicate delivery/credit handling. It is not a
process-crash, live-model, Iroh or Sui test.

The six steps authorize 14 MIST, deliver one input byte and the first four output
bytes, authorize a cumulative 38 MIST, deliver the remaining four output bytes,
and retain a final checkpoint. The first output chunk ends inside the four-byte
globe character in `Hi 🌍!`; use a streaming decoder per request. Delivered price
is 26 MIST. Historical signed authorization is 38, not 14 + 38. Final consent
alone leaves 12 MIST of signed authorization above delivery: chain settlement is
deliberately absent (`chain_observation: null`). A browser fixture can label its
own injected chain observations separately, but must not infer confirmation or
refund from this consent. Signatures in this file prove only fixture statements,
not the existence, funding, authority or settlement of any public-chain object.

This economic input bundle is not an event schema or a valid complete HTTP
snapshot. Tests must wrap it using the shared public event contract and provide
explicitly labeled, internally consistent test identities/status. Do not serve
this file from the production app or use its accounts for funds.

`public-session.ts` exports `createPublicSessionFixture()` for shared tests. It
wraps those same signed statements in a coherent snapshot and contiguous public
event history, with canonical IDs, separate 32-byte transport/economic keys,
receipt byte counts, and matching 2/3 rates. Its host/model/tool/identity metadata
is explicitly synthetic, not generated by running agents or querying a chain.
`npm run agent-demo-public-fixture-tests` checks its signatures, references,
source/merged cursors, UTF-8 reconstruction and exact accounting independently.
It also feeds the retained credit/delivery inputs through the actual BudgetLedger,
checks duplicate reservation, and compares its reopened journal snapshot with
the public budget. Those are injected accounting inputs, not chain observations.
That coherence oracle does not validate an HTTP endpoint or browser consumer.

The snapshot is a complete history cut at `snapshot.projection_sequence` and
contains no transcript itself. Replaying its events must rebuild history without
reapplying old financial/control state or money animations. The baseline has no
chain observations: channel state is unknown, actual redeemed/locked/refund
values and transaction digest/gas are null, and final consent retains 12 MIST
exposure. Do not replace unknowns with zeros to simplify a test screenshot.
Hypothetical chain observations in separate tests must be labeled as separately
injected inputs. All rendered fixture captures must include the `notice` outside
the production envelope in a test-only harness; mocked responses at production
routes are still fixtures and must not be presented as a live exchange.
